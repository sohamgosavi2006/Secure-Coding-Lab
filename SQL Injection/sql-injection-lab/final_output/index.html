Understanding SQL Injection & The Secure Coding Fix

How query structure and untrusted data become dangerously intertwined, and the mathematical remedy of parameterized queries.

🛡️

Golden Rule of Secure Coding: Separation of Code and Data

Never concatenate or interpolate user input directly into SQL statement strings. Always compile the query structure first using the database driver, and pass untrusted user input as bound parameters.

⚠️ Anatomy of the Login Bypass Attack

When a developer uses string concatenation like query = "SELECT * FROM users WHERE username = '" + username + "'", the database grammar treats quotation marks inside username as structural delimiters rather than data characters.

  • The Single Quote ('): Prematurely closes the developer's opening quote literal for the username field.
  • The Logical OR (OR 1=1): Injects an expression that is mathematically always TRUE (a tautology). In boolean logic, FALSE OR TRUE evaluates to TRUE.
  • The SQL Comment (--): Tells the SQLite engine that all text following the double dash is a comment. This completely neutralizes the AND password = '...' clause!
  • The Result: The database returns all records matching 1=1 (every row in the table). cursor.fetchone() selects the first row, granting instant administrative access.

🛡️ Why Parameterized Queries Are Immune

Parameterized queries (also called prepared statements) decouple the query structure from the user-provided data:

  • Pre-compilation: The database engine parses, optimizes, and compiles the SQL syntax tree with placeholders (?) before receiving any parameter values.
  • Strict Data Typing: Bound parameters are passed separately through the database driver protocol as raw literal values.
  • Character Neutralization: If a user enters ' OR 1=1 --, the database looks for a record whose username column literally equals the 11-character string ' OR 1=1 --.
  • Zero Parsing Ambiguity: Quotes are not delimiters, OR is not an operator, and -- is not a comment marker. The injection cannot execute.

Implementation Code Comparison (Python SQLite)

❌ Vulnerable Code
def authenticate(username, password): conn = sqlite3.connect("db.sqlite") cursor = conn.cursor() # Flawed string concatenation: query = ( "SELECT * FROM users " f"WHERE username = '{username}' " f"AND password = '{password}'" ) cursor.execute(query) return cursor.fetchone()
✅ Secure Code (Remediation)
def authenticate(username, password): conn = sqlite3.connect("db.sqlite") cursor = conn.cursor() # Parameterized query with placeholders: query = ( "SELECT * FROM users " "WHERE username = ? AND password = ?" ) cursor.execute(query, (username, password)) return cursor.fetchone()
